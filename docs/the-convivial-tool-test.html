The Convivial Tool Test

A design heuristic for evaluating whether a tool serves the people using it.

Ivan Illich, 1973: "A convivial tool extends human capability; an industrial tool creates dependency."
1
Capability Extension
Does the tool make its users more capable, or more dependent?
After six months, are users more able to accomplish their goals — including without the tool — or less able? A tool that builds skill is convivial. A tool that deskills is industrial.
Positive: Users develop transferable understanding. An AI that drafts for human refinement.
Warning: Learned helplessness. Users cannot explain what the tool does.
2
Legibility
Does the tool make its own workings visible to its users?
Functional transparency: what it does, how it does it, what data it uses, what decisions it makes, and why.
Positive: Operations inspectable. Protocol Stream shows state transitions.
Warning: Opaque black box. Operators know more than users.
3
Governability
Can the community that uses the tool govern its evolution?
Users have structural authority: set priorities, veto changes, participate in roadmap decisions.
Positive: Community governance. Open-source with real voting.
Warning: Voice without vote. Unilateral terms changes.
4
Proportionality
Is the tool scaled to the community it serves?
Powerful enough for needs, modest enough not to restructure the environment around itself.
Positive: Fits actual scale. Treasury for actual transaction volume.
Warning: Requires community to scale up to use it. Enterprise for ten people.
5
Reversibility
Can the community stop using the tool without catastrophic loss?
Data portable, processes documented, knowledge persists. The community could switch or go manual.
Positive: Event-sourced history recoverable. Standard accounting.
Warning: Vendor lock-in. Workflow restructured around tool.

The Vitruvian Principle

Like firmitas, utilitas, venustas, the five qualities cannot be optimized independently. A tool that extends capability brilliantly but cannot be governed will betray that extension. A legible tool that is disproportionate will be transparently wrong-sized.

The heuristic is not a score. It is a way of seeing. Each quality illuminates something different about the tool's relationship to its users. The conversation they produce is the evaluation.

This is a working document. It will evolve as the cooperative uses it. The first test of a design heuristic is whether the community that created it can govern its evolution.
